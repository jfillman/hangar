# web: hangarplatform.dev

The Hangar website: platform engineering from James Fillman's point of view, with Hangar as the working
implementation. Astro, static, deployed to GitHub Pages by `.github/workflows/pages.yml`.

```bash
npm ci
npm run dev      # http://localhost:4321
npm run build    # writes dist/
```

## Where things come from

- **Diagrams are not copied into git.** `scripts/sync-assets.mjs` (run by `dev` and `build`) copies
  `docs/autopilot/diagrams/{plan,autopilot,reference}` (generated by `tools/diagrams/build_hangar.py`), the brand
  marks and two brand pages into `public/`, and writes `src/data/diagrams.generated.json`. Regenerate a diagram in
  `tools/diagrams`, and the site picks it up on the next build.
- **Glidepath's SVGs** live in another repo, so they are vendored in `vendor/glidepath/`. With a sibling
  `../glidepath` checkout, the sync script refreshes them.
- **Words** live in `src/data/` (`principles.ts`, `sdlc.ts`, `products.ts`) and in the pages under `src/pages/`.
  Every claim carries a status (Built, Draft, Proposal); keep it honest when the platform changes.
- **The log** is `src/pages/log.astro`; add new entries at the top.

## Deploying

One-time: Settings > Pages > Source: **GitHub Actions**, then set the custom domain (`hangarplatform.dev`) on the
same page once DNS points at GitHub. The workflow takes the URL and base path from `actions/configure-pages`, so the
same build works at `jfillman.github.io/hangar/` before the domain is live.

Release record · 01 of 03 · The shape

One release, and where each step is written

A release is followed from the moment the one before it ships until anyone can say how it went. Every step a person decides lands in git as a commit or a pull request. Only the part that is still moving lives on a cluster.

Starts early

The draft exists before any pull request does, so notes get written while the work merges, not the night before.

Sealed in git

The record is a YAML file in the app's gitops repo, added by a pull request. Tower reads it back; it never owns it.

Ends late

A release is not done at healthy. The outcome is written into the same file once the bake window says how it went.

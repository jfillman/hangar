Break-glass · 01 of 07 · The idea

Exec, or a debug container?

Both give you a shell next to the app. Only one of them hands the cluster something it can inspect before saying yes.

All or nothing

Exec is a single verb on a single subresource. A policy can refuse it or allow it, and nothing in between.

Inspectable

An ephemeral container arrives as a full spec: image, user, capabilities, mounts. Every field is something a policy can check.

Not safe by nature

Run as the app's user with its process namespace shared, a debug container reaches the same secrets as exec. That is why process access is a separate, recorded opt-in.

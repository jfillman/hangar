Break-glass · 05 of 07 · The policies

Six admission policies, one per thing that could go wrong

The backend is the first lock. These are the second, inside each cluster's API server, written so that a bug in Tower, or a compromised Backstage, still cannot turn a debugging session into something bigger.

Native first

Validation runs as built-in ValidatingAdmissionPolicy, inside the API server. It cannot be down on its own, which matters most during the incident you opened the session for.

One webhook, fenced

Only the image signature needs Kyverno's webhook. Its match conditions are copied onto the webhook, so it never sees a request that is not break-glass.

Learned the hard way

An unguarded CEL field once refused every pod create on the dev cluster for ten minutes. Now every optional field is guarded and every policy is scoped.

# AGENTS.md: Airframe

Airframe is Hangar's service catalog: Crossplane XRDs, compositions and the `airframe-application`
Helm chart. Its **contract is machine-readable**. Read the contract, not the prose.

## Start here
1. `contract/airframe-contract.json`: every stack, component, field, default, owner, risk and output.
   (Generated by CI on each tag. Until it exists, read `charts/airframe-application/values.schema.json`
   and `xrds/*.yaml`.)
2. `airframe.capabilities` and `airframe.explain <field>` if you have the tools.
3. `docs/walkthroughs/` for worked, replayable examples.

## The model in five lines
- **Bootstrap tier** (`NodeJSApplication`, `PythonApplication`, `SpringBootApplication`, `GoApplication`, `InfraService`): creates repos and onboarding. Not a Deployment.
- **Ground** environment: `platform/envs/<env>.yaml` in the app repo, dev cluster only.
- **Flight** environment: an `ApplicationEnvironment` XR, rendering `gitops-<app>/<cluster>/<env>/values.yaml`.
- **Components** (Redis, PostgreSQL, RabbitMQ, ...) are entries in `components:` of an environment's values.
- One GitOps write path. Nothing is applied with `kubectl`.

## Do
- **Plan, validate, then open a PR.** `airframe.plan` returns a diff and a validation report; `airframe validate` is a required check.
- Reference a component's output with `fromComponent`. Never hand-write `cache-master` or `<name>-connection`.
- Set `devCluster` from the registry (it is `kind-dev` even though the cluster is `kiac-dev`).
- Put config in the human-owned file. Wait for the release file's owner (Glidepath) to write image and release keys.
- Read the `rule` and `hint` in a validation failure and change the file. Retry at most three times, then stop and report.

## Do not
- Edit machine-owned keys (`x-hangar-owner: release`): `releaseTracking`, `rollout.image`, and anything in `*.release.yaml`.
- Use `extraManifests`, `networkPolicy` or `httpRoute` without a human's approval (`x-hangar-risk: high` or `critical`).
- Put a secret value in `env` or `configMaps`. Secrets are references to Infisical keys.
- Name an environment after a pipeline stage (`build`, `test`, `deploy`, `release`).
- Configure `rollout` before an image exists unless the chart guard is present (`AF-ROLLOUT-001`).
- Change a shared XRD or composition in place. Test a copy through one XR's `compositionRef`.
- Commit, tag or push to a shared checkout without checking the branch and using a worktree.

## Verify
`airframe.verify` runs each component's and each app's verify contract and returns evidence. A green
pipeline is not verification; the service is.

## Errors
Rule ids are `AF-<AREA>-NNN` (see the contract). Every rule has a hint. If a rule blocks you and you
believe it is wrong, say so in the PR. Do not work around it.

Tower, judged again as my only console

Four weeks after the first report I sat in the same seat and asked the same question. The answer moved a long way. What's left isn't a missing button any more. It's the ground the console stands on.

Yes for looking · now yes for acting

The console is finished enough. The platform under it is the next report.

  • Every gap in the first report but one is closed, and closed the hard way: Tower still holds no Kubernetes write access of its own. Every write goes through Argo CD or a reviewed PR, behind 18 per-app permissions, and every action is audited, refusals included.
  • Rollback, Rollout controls, force sync, terminate, pod restart, image cleanup and a two-person break-glass debug container all exist, and I tested them in a browser this week.
  • What still sends me elsewhere is underneath: the prod cluster has no metrics, prod leans on the dev cluster, gates can't block a merge on GitHub's free plan, and nothing is backed up.

The original four, then and now

The biggest move is release management. Roll back opens a rollback release PR against a healthy earlier release, where integrity gates block and content gates only advise, and I tested abort and retry live on a Skyport app's staging. Release state is now built from the Rollout's own facts (ADR-0021) instead of hook Jobs. And the plain-language troubleshooting banner on Deployments is the single best reason I no longer open the Argo CD UI for an app I own.

The backlog, ordered by what unblocks trusting prod

The first report's backlog was about adding levers. This one is about the floor under them. Three items were done the day after it was written.

Quick wins

Close the Kubernetes proxy hole first

Done Oct 12, 2026

The read token behind the portal could do far more than read, and any signed-in user could reach it through a generic proxy. Phase 0 of the credentials spec closed it.

Give Flight environments a Prometheus to read

Done Oct 23, 2026

Until then SLOs, pod metrics and canary analysis are empty for exactly the environments an owner cares about. The prod profile now runs Prometheus and tracing, and Tower reads every cluster through the hub's Thanos.

Decide on scale, then close the question

Open

Durable scale already exists as a values PR. My recommendation: no runtime scale, and say so.

Finish break-glass hygiene on Flight

Open

A signed debug image, an image policy scoped to debug containers, and a cleanup backstop in the cluster.

Confirm the image cleanup token really synced

Open

If it never did, the Images tab's one write action is dead on prod.

Show test results where releases are judged

Done Oct 19, 2026

Testkube results belong on the Release Record and the pipeline row. Tower v0.79 and v0.80 put every attested test run on the image, a Tests view on Pipelines, and the test evidence on the Release Record.

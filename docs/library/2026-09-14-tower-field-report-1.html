Tower · Field report I · The app owner's seat

Tower, judged as my only console

Tower set out to be the one place an app owner goes. So I sat in that seat and asked a blunt question: for the apps I own, end to end, would I actually give up kubectl, Argo CD, the Tekton dashboard and a release tool for this? I scored each one on three things: can I see it, can I change it, and does Tower give me enough to own the outcome without leaving.

Mostly for looking · not yet for acting

The visibility problem is solved. The authority problem is next.

Tower already answers "where do I go to see what's happening": one URL, one app, nine tabs, real data from Kubernetes, Tekton, Argo CD, GitHub and Prometheus. The acting half is thinner. Promote and Config edits are real, careful write paths, but there's no rollback, no way to unstick Argo CD, no re-run of a failed pipeline, and no restart on a workload. Those are exactly the moments an owner reaches for a console under pressure.

The instrument panel

Signal and noise

Genuinely worksStill sends me elsewhere
One app, one URL, nine tabs. Overview, PRs, CI/CD, Releases, Topology, Images, SLOs, Notifications and Config, with no plugin-hopping.No rollback. A bad release only moves forward; reverting means a hand-built PR.
PR context everywhere. State, CI and review status ride on the same button wherever a PR matters.No exec, port-forward, restart or scale. Every "act on the workload" moment means a terminal.
Config edits are real GitOps. Form fields where they fit, a YAML editor where they don't, and every save checked against the chart's schema before it becomes a PR.No manual sync or re-run. Both are read-only observation decks.
SLOs are the real thing. Multi-window burn rates from live Prometheus, with a plain-language explainer.No app-level authorization. Who may promote to prod is whatever branch protection says, invisible to Tower.
Shared plumbing. One cluster-aware fetch backs Topology, logs, events and Tekton polling.No single audit trail. Config PRs, promotions and deploys each leave their own trace somewhere else.
A fleet view too. The Fleet Grid and Ops Wall answer "how's everything doing".Secrets, attached infrastructure and cost stay out of scope.

Strategic

A real per-app authorization model

Done by Oct 11, 2026

Anyone signed in could Promote or edit Config. The only gate was GitHub review, which Tower couldn't see. Since: 18 permissions, owners and admins, grant-only Flight actions, audited.

Done by Oct 11, 2026

The biggest reason an owner still opens a terminal, and the action with the most blast radius. Since: Break-glass debug containers instead of exec, two-person on Flight.

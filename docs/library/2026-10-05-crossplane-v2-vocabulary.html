Is "claim" the right word in a Crossplane v2 world?

I use Crossplane v2 exclusively, and one word kept rubbing me the wrong way: "Ephemeral runs are claims to Crossplane." I asked ChatGPT to analyse it, then had Claude check that analysis against the v2 docs and every repo. This is what held up, what didn't, and what changed.

"Claim" was the wrong word. "Direct request" says what's actually different.

Crossplane v2 removed Claims: namespaced XRs don't need them, and only LegacyCluster XRs from v1 XRDs still support them. So a Crossplane reader who sees "AgentRun claim" assumes v1 indirection that Hangar never used. The fix was mostly words, because nothing in Hangar was ever built on Claims.

  • Principle, now: Durable changes are git commits. Ephemeral runs are direct requests to Crossplane.
  • Any Crossplane object is an XR (a namespaced composite resource), never a claim.
  • Autopilot's narrow-only request is called requested limits (LimitRequest in code, passed as limits).

What changed in v2

The whole reason for a Claim was that v1 XRs were cluster-scoped. Namespaced XRs remove that reason, and v2 removes Claims with it. Every Airframe XRD and the draft AgentRun XRD are apiextensions.crossplane.io/v2, scope: Namespaced, with no claimNames.

Where the analysis was right, and where it slipped

Right

The core point

"Claim" signals v1 to anyone who knows Crossplane. The v2 docs say it plainly: namespaced XRs don't support claims.

Overstated

It's prose, not the model

Nothing in Hangar was built on Claims. "Kubernetes API for AgentRun claims" in a README is wording, not an implementation choice.

Missed

Its favourite fix

"Ephemeral runs are Crossplane XRs" doesn't separate the planes, because durable apps are XRs too. The difference is the path.

Missed

How far it went

The word was all over the site: the glossary, the stack page, the cost essay's rule of thumb and the overview diagrams.

Missed

Two meanings in Autopilot

One was the AgentRun. The other was the narrow-only request in code, which also applies to local sessions and child spawns. It needed its own name.

The two planes, named by their path

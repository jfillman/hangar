One release, start to finish, on GitLab

This is the acceptance test for phase 3: a new Skyport service, scaffolded from Tower, built, signed, released to a Flight environment and rolled back, with no GitHub anywhere in the path. Every step already exists on GitHub; the only new parts are the drivers.

Principle honored

Glidepath's engine does not change. Pipelines as Code already accepts GitLab webhooks and reports commit statuses, and Argo CD already pulls from any git host.

What changes

  • The webhook is per project, so onboarding creates it as an scm.hangar.io Webhook.
  • The merge gate is a protected branch with required approvals and "pipelines must succeed".
  • Release MR, comments and statuses go through the scm CLI.

Done when

Not run yet. The lab has no GitLab group. Phase 3 is done when this sequence has run live, end to end, including a rollback, and the merge gate refused a merge with a red gate.

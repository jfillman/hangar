Portability · 03 of 06 · Credentials

A short-lived token on every forge

Hangar's rule is that a pipeline never holds a standing credential: it proves who it is and gets a token for one repository. The broker keeps that rule on every forge. What it cannot keep is the lifetime and the scope, and those differ.

Same front door

The broker's caller check does not change: a Repository CR in your namespace, proved with TokenReview. Only the minting step is per forge.

Two weaker spots

  • GitLab tokens expire by date, so a token can live up to a day. The broker revokes it when the run ends.
  • Bitbucket Cloud OAuth tokens cover the whole workspace. Use one workspace per trust boundary.

One new standing secret

Pipelines as Code on GitLab and Bitbucket reads a token from a Secret named by the Repository CR. The broker rotates it daily and Tower shows its age.

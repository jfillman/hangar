API · 02 of 03 · Auth

How glidepath-api decides a call

Authentication is the cluster's TokenReview. Authorization is ordinary RBAC on a group nothing serves. Every refusal has a name an agent can branch on, and nothing goes unrecorded.

Who

Anything the cluster trusts works: an in-cluster ServiceAccount, a federated identity from the other cluster, or since November 1 a person signed in with people-dex.

What

runs, runs/logs, releases, evidence, tests, environments, events and cicd: strings in a ClusterRole. Three roles, reader, operator and releaser, and all of them empty on a fresh install.

For whom

Tower writes as tower-actor and names the person. The API authorizes Tower and records the person; Tower checks ownership before it calls.

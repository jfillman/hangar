One test run in Hangar

The app team writes one file. Glidepath does the rest: it moves the secrets in for the length of the run, applies the workflow through a policy gate, and puts the result where people already look.

Self-service

A new test is a file in the app repo, next to cicd.yaml. No ticket, no operator, and the name can't collide with another app's.

Fenced

Kyverno checks every TestWorkflow at admission, while the caller's real identity is still visible. One app's tests can't mount another app's secrets.

Not only tests

A TestWorkflow is anything that runs and reports pass or fail. Warming a cache before a release fits just as well as a Playwright suite.
